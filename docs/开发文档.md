# 全局翻译自动朗读 · 开发文档

> 版本 v0.1（2026-10-30）· 状态：待评审 · 形态：macOS 原生桌面 App（菜单栏常驻 + 划词浮条 + 截图 OCR）
> 本文是唯一的开发基准：接口契约、UI 规格、验收数字都以本文为准；实现偏离本文必须先改本文。

---

## 1. 定位与目标

**一句话**：一个 macOS 划词/截图即翻译的工具，**只朗读原文**（不朗读译文），译文与词条细节以千问式浮窗 + 有道式词典卡片呈现，翻译走用户自填的 OpenAI 兼容大模型 API。

### 1.1 必须成立的三件事

| 编号 | 目标 | 判据 |
|---|---|---|
| G1 | 划词即译，零打断 | 在任意 App 选中文本后，浮条 ≤150ms 出现，且不抢焦点、不打断输入 |
| G2 | 原文秒出声 | 从触发到听见第一个字 ≤400ms（系统 TTS 通道） |
| G3 | 自带模型 | 只依赖用户填写的 baseURL/apiKey/model，不绑定厂商、不上传除文本/截屏外任何数据 |

### 1.2 非目标（本版不做）

- 不做对话框式聊天（不做多轮问答 UI），产品是「翻译 + 朗读 + 词条细节」，不是 AI 助手。
- 不做译文朗读（用户明确：仅朗读翻译前的原文）。译文不提供喇叭按钮。
- 不做 Windows/Linux（若后续要，见 §11 R1 的技术栈重估）。
- 不做 App Store 分发与公证（本版仅本地自签名运行）。
- 不做离线翻译（翻译必须联网；OCR 与朗读可离线）。

## 2. 用户故事

1. 在微信/浏览器里看到不认识的英文，选中 → 浮条出现在选区右上方 → 点「翻译」→ 弹窗显示原文（带喇叭，自动朗读一遍）+ 译文 + 用法出处；点喇叭可复读。
2. 看到图片/PDF 里的外文，按 `⌥S` → 屏幕变暗可拖框 → 松手 OCR → 自动翻译 + 朗读原文。
3. 只想听不认识的句子怎么读：选中 → `⌥R` 复读上次原文。
4. 学单词：单词模式给出词条卡（词性分组、义项、例句、近义），对标有道「简明/新汉英/例句」结构。
5. 换模型/换语言：设置里切语言方向（英汉互译、日汉、韩汉、法汉、德汉、俄汉、葡汉、西汉、自动检测 + 全部语言自定义），切「标准 / 高级」两档模型。

## 3. 产品规格

### 3.1 划词浮条（Selection Bar）

- **触发**：任意 App 内选中文本后自动出现（可在设置里关闭，改为仅快捷键触发）。
- **位置**：选区包围盒右上角 +8pt，贴近屏幕边缘时自动翻转；不遮挡选区本身。
- **窗口类型**：`NSPanel`，`styleMask = [.nonactivatingPanel, .borderless]`，`level = .statusBar`，`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .transient]`。**绝不 `makeKeyAndOrderFront`**（会抢焦点并杀掉用户的选区）。
- **内容**（对标千问浮条）：`[logo] [文A 翻译] [···]`，右侧「···」展开二级菜单：复制 / 朗读原文 / 收藏 / 用高级模型重译。
- **消失**：点击外部、`Esc`、选区清空、输入焦点变化（轮询 5Hz，最多 2s 超时后隐藏）。
- **不应出现的场景**：目标 App 是自身、密码框（`AXSecureTextField`）、选区为空、纯数字/单字符、用户已禁用、App 在黑名单中。

### 3.2 主弹窗（Translation Card）

参考两张图：整体交互与信息层级抄 **千问**（深色卡片、悬浮、可拖动、底部图标条），词条排版与顶部工具条抄 **有道**。

结构自上而下：

1. **顶栏**：语言方向下拉（自动检测 / 英汉互译 / 日汉互译 / 韩汉互译 / 法汉互译 / 德汉互译 / 俄汉互译 / 葡汉互译 / 西汉互译 + 分隔线下「全部语言」两个选择器）｜右对齐 `AI模型 [标准][高级]` 分段控件｜`×` 关闭。
2. **原文区**：原文文本（可选中）。左侧 `🔊` 喇叭按钮 → 朗读/复读原文（播放中变波形动画，再点即停）。右上角复制按钮。
3. **译文区**：流式逐字出现；底部一行图标条：复制 / 赞 / 踩 / 分享 / 重新生成 / 更多。
4. **细节区**（异步加载，不阻塞译文）：分 tab `简明 · 新汉英 · 例句 · 百科`（单词模式）或 `译文 · 替代译法 · 用法 · 出处`（句子模式）。内容全部来自 Stage2 结构化响应（§6.5）。
5. **底部输入条**（可选，默认折叠）：仅用于「改一句再译」，不做对话。

尺寸与行为：默认 420×≤560pt，内容自适应高度上限 560pt 后内部滚动；可拖动；失焦自动关闭（可设置）；`⌘W`/`Esc` 关闭；记住上次位置。

### 3.3 朗读交互（本产品的核心差异点）

| 规则 | 说明 |
|---|---|
| 只读原文 | 译文区没有喇叭；原文区喇叭在左，点击即读 |
| 自动读一次 | 弹窗打开后自动朗读原文一遍（设置项 `自动朗读` 可关） |
| 复读 | 点击喇叭 = 从头重读；播放中点击 = 立即 stop |
| 打断 | 新原文到达时立刻 stop 旧朗读再播新句（不排队混音） |
| 分句 | 长文本按句末标点与换行切句，逐句合成、边合边播，队列上限 3 句 |
| 多语言 | 按原文语种选音色（§6.6），设置里每种语言可指定偏好音色、语速 0.5–1.5×、音量 |
| 隐私 | 本地合成或只把文本发给用户配置的端点；朗读音频不回传厂商 |

### 3.4 截图 OCR 翻译

- `⌥S` 触发 → 全屏变暗（黑 25% 透明）+ 十字光标 → 拖框（带尺寸提示、`Esc` 取消、`Space` 改全屏）→ 松手即截。
- 捕获用 `SCScreenshotManager.captureImage`（ScreenCaptureKit，macOS 14+），只截选区，输出 `CGImage`。
- OCR 用 Vision `VNRecognizeTextRequest`：`recognitionLevel = .accurate`、`usesLanguageCorrection = true`、`recognitionLanguages` 按设置注入（默认 `zh-Hans, en-US, ja-JP, ko-KR`），按行聚合后纵向排序，保留换行结构。
- OCR 结果先进「可编辑确认态」（内联展示，可直接改错字），确认后自动翻译 + 朗读。
- 截图默认不入磁盘；仅在用户开启「保存 OCR 原图」时写入 `~/Library/Application Support/<app>/ocr/`，30 天清理。

### 3.5 设置面板（对标千问设置页结构）

`翻译引擎`（默认引擎 机器 / AI、机器翻译服务商、测试机器翻译；选 AI 时才有 baseURL、apiKey、模型名标准/高级、测试连接）· `通用`（开机自启、语言方向默认值、自动朗读、失焦关闭）· `快捷键`（录制器 + 冲突检测 + 重置；默认 `⌥Space` 翻译、`⌥S` 截图 OCR、`⌥R` 复读、`⌘,` 设置）· `朗读`（引擎、音色、语速、音量、试听）· `划词`（启用、黑名单 App、仅快捷键模式）· `历史`（条数上限、清空、导出）· `关于`（版本、权限自检入口）。

### 3.6 菜单栏

模板图标（跟随明暗）→ 翻译剪贴板 / 截图 OCR / 复读上一条 / 历史 / 设置 / 权限自检 / 退出。左键菜单，`⌥`+左键直接截图（可设置）。

## 4. 视觉规格

### 4.1 颜色 token

浅色与深色双主题，默认跟随系统。参考图取色：有道卡片底色 `#F8F8F8`，千问深色卡片主色 `#484848 / #404048 / #282828`。

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `surface` | `#F8F8F8` | `#282828` | 卡片底 |
| `surfaceElevated` | `#FFFFFF` | `#404048` | 浮条/输入条 |
| `surfaceSunken` | `#F0F0F0` | `#1F1F1F` | tab 未选中、hover |
| `textPrimary` | `#1A1A1A` | `#F2F2F2` | 原文/标题 |
| `textSecondary` | `#666666` | `#A8A8B0` | 词性、说明 |
| `accent` | `#2F6BFF` | `#5B8CFF` | 词条/链接/播放中 |
| `divider` | `#E0E0E0` | `#3A3A40` | 分隔线 |
| `danger` | `#D93B3B` | `#FF6B6B` | 错误 |

### 4.2 排版

- 原文：16pt / 行高 1.5 / Regular；译文：17pt / Medium；词条标题：17pt / Semibold / `accent`。
- 词性标签：12pt / 斜体 / `textSecondary`；义项序号 12pt `textSecondary`，悬挂缩进 18pt。
- 喇叭按钮：16pt system symbol，播放中显示 3 帧波形动画，`reduceMotion` 为真时改静态高亮。
- 圆角：卡片 12pt，浮条 10pt，按钮 8pt。浮条阴影 y=2 blur=12 alpha=0.18。

### 4.3 状态矩阵

| 状态 | 表现 |
|---|---|
| 加载译文 | 译文区 3 行 skeleton 呼吸动画；喇叭可点（朗读不依赖翻译） |
| 加载细节 | 细节区顶部 2pt 进度条，可交互 |
| 网络错误 | 译文区红字 + 「重试」按钮，显示状态码与端点主机名（不显示 key） |
| 无 API key | 弹窗内嵌「去配置模型」按钮，直跳设置 |
| 未授权 | 首次截图前显示系统授权引导卡片（含「打开系统设置」深链） |
| TTS 失败 | 喇叭变灰，tooltip 显示原因；不阻断翻译流程 |

## 5. 技术栈与架构

### 5.1 选型（决策）

| 层 | 选择 | 理由 | 放弃的备选 |
|---|---|---|---|
| UI | Swift 6 + SwiftUI（AppKit 处理 NSPanel/热键/覆盖窗） | macOS 独占，零运行时依赖，常驻内存最小 | Electron：+200MB、截图/OCR 要外挂；Tauri：WebView 做 nonactivating 浮条与 TCC 处理反而更绕 |
| 构建 | SwiftPM（`swift build -c release`）+ 脚本手工组装 `.app` | 本机只装 CommandLineTools（无 Xcode），`xcodebuild` 不可用 | 依赖 Xcode 的工程文件：本版不采用 |
| OCR | Vision `VNRecognizeTextRequest` | 系统内置、无模型下载、中文质量好 | tesseract：体积与精度都更差；云 OCR：隐私与费用 |
| 截图 | ScreenCaptureKit `SCScreenshotManager` | 系统级、直接截区域、避开已废弃 API | `CGDisplayCreateImage`：已废弃且权限行为不稳 |
| 划词取文 | Accessibility `AXSelectedText` 主路径 + `⌘C` 剪贴板兜底 | 兼容性最好 | 仅 `⌘C`：污染剪贴板、触发部分 App 的保护 |
| 全局热键 | Carbon `RegisterEventHotKey` | 不需要「输入监控」权限 | `CGEventTap`：多一项 TCC 权限，易被安全软件拦 |
| 存储 | SQLite（GRDB）+ Keychain + UserDefaults | 历史可查、key 不落明文 | SwiftData：迁移与查询控制力弱 |
| 翻译 | OpenAI 兼容 `POST /chat/completions`（stream） | 用户自填，任何中转站/本地模型都能接 | 各家原生 SDK：绑死厂商 |
| 朗读 | 引擎协议 + 三实现（系统 AVSpeechSynthesizer / OpenAI 兼容 `/audio/speech` / 本地 sherpa-onnx） | 默认零内存零延迟，需要音质再升级 | 只做云 TTS：延迟+费用+隐私；只做本地：中文音质与体积取舍 |

### 5.2 模块划分（SwiftPM targets）

| Target | 职责 | 主要依赖 |
|---|---|---|
| `AppShell` | 菜单栏、生命周期、单实例、权限自检 | AppKit, SwiftUI |
| `HotkeyKit` | 全局热键注册/录制/冲突检测 | Carbon |
| `SelectionKit` | AX 选区读取、剪贴板兜底、浮条定位 | ApplicationServices |
| `OverlayKit` | 浮条与弹窗 NSPanel、主题 token | AppKit, SwiftUI |
| `CaptureKitX` | ScreenCaptureKit 截图与区域选择器 | ScreenCaptureKit |
| `OCRVision` | Vision 文字识别、行聚合、语种判定 | Vision, NaturalLanguage |
| `TranslateKit` | Provider 协议、OpenAI 兼容实现、SSE 解析、重试、缓存 | URLSession |
| `SpeechKit` | `SpeechEngine` 协议与三实现、分句队列、打断 | AVFoundation（本地引擎为可选依赖） |
| `Store` | 历史/收藏/设置、Keychain | GRDB, Security |
| `DesignSystem` | 颜色/字体/组件（喇叭按钮、词条行、tab） | SwiftUI |

依赖方向单向：`AppShell → 其余模块`；模块之间只通过协议交互，`DesignSystem` 不依赖业务。

### 5.3 关键时序

**划词路径**

```
用户松手 → AX 轮询(120ms 内) 读 AXSelectedText
  ├─ 命中 → 算包围盒 → 显示浮条(nonactivating) → 点「翻译」
  └─ 空 → 保存剪贴板 → 合成 ⌘C → 读剪贴板 → 恢复剪贴板（changeCount 校验，失败则不覆盖）
→ 打开弹窗：立即用系统 TTS 朗读原文（不等翻译）
→ 并发：Stage1 流式译文 / Stage2 结构化细节
→ 渲染 原文(喇叭) + 译文流 + 细节
→ 写历史（成功与否都写一条，失败带错误标记）
```

**截图路径**

```
⌥S → 遮罩窗(每屏一个, 全屏) → 拖框 → SCScreenshotManager.captureImage(region)
→ Vision OCR(后台) → 可编辑确认态 → 翻译(同划词路径) + 朗读
```

### 5.4 并发与线程

- UI 全部 `@MainActor`；OCR / 网络 / 合成各用独立 actor。
- 单飞：同一 `(文本, 语言对, 档位)` 的并发请求合并为一次。
- 取消：弹窗关闭 → 取消 Stage1/Stage2 的 Task 与 SSE 读取；朗读 `stop()`。

## 6. 关键模块设计

### 6.1 选区读取（SelectionKit）

```swift
protocol SelectionReading { func currentSelection() async -> Selection? }
struct Selection { let text: String; let bounds: CGRect; let appBundleID: String; let isSecure: Bool }
```

- 主路径：`AXUIElementCreateSystemWide()` + `kAXFocusedUIElementAttribute` → `kAXSelectedTextAttribute`（取文）与 `kAXSelectedTextRangeAttribute`（取包围盒）。
- 兜底：保存 `NSPasteboard.general` 全量项 → 发送 `⌘C` → 轮询 `changeCount`（150ms）→ 读字符串 → 恢复原项。用 `changeCount` 前后比对判定用户是否在此期间改动剪贴板，**若改过则不恢复**，避免破坏用户数据。
- 隐私闸门：`AXSecureTextField` 角色 / `isSecure` / Bundle 黑名单 → 一律不读、不显示浮条。

### 6.2 浮条与弹窗窗口（OverlayKit）

- `SelectionBarPanel`：`NSPanel(contentRect:styleMask:[.nonactivatingPanel,.borderless],backing:.buffered,defer:false)`，`becomesKeyOnlyIfNeeded = true`，`canBecomeKey = false`（按钮用 `NSHostingView` 自绘点击，不依赖 key）。
- `TranslationPanel`：同样 nonactivating，但允许成为 key 以便文本选择；`Esc` 走本地事件监听。
- 多屏与全屏 App：遍历 `NSScreen.screens` 选包含选区的屏，`collectionBehavior` 含 `.fullScreenAuxiliary`。

### 6.3 截图与 OCR（CaptureKitX / OCRVision）

```swift
struct OcrLine { let text: String; let confidence: Float; let box: CGRect }
struct OcrResult { let lines: [OcrLine]; let detectedLanguage: String?; let elapsedMs: Int }
```

- 屏蔽自身：截图前把浮条/弹窗 `orderOut`，截完恢复，避免 OCR 到自己的 UI。
- 行合并：按 `boundingBox.minY` 降序聚合（阈值 = 行高 0.5），同段落按行间距阈值拼接；全角标点原样保留，不自动换半角。
- 语种：优先 Vision 候选语言 + `NLLanguageRecognizer` 兜底；置信度 <0.6 时提示「语种可能不准确，可手动切语言方向」。

### 6.4 语言方向

```swift
enum LangCode: String { case zhHans = "zh-Hans", zhHant = "zh-Hant", en, ja, ko, fr, de, ru, pt, es, it, ar, th, vi, auto }
struct LanguagePair { var source: LangCode; var target: LangCode }
```

- 预设对齐有道下拉：自动检测 / 英汉互译 / 日汉 / 韩汉 / 法汉 / 德汉 / 俄汉 / 葡汉 / 西汉。
- 自动检测：含 CJK 表意文字 → 中文（并判繁简）；否则按假名 / 谚文 / 西里尔 / 拉丁语种字典；再失败用 `NLLanguageRecognizer`。
- 「全部语言」：两个 Picker 列 ISO 639-1 全集，目标语言默认 `zh-Hans`。

### 6.5 翻译 Provider（TranslateKit）

**协议**

```swift
protocol TranslateProvider {
    func translate(_ req: TranslateRequest) -> AsyncThrowingStream<TranslateEvent, Error>
}
enum TranslateEvent { case delta(String); case detail(TranslationDetail) }
```

**请求**（OpenAI 兼容）

```json
POST {baseURL}/chat/completions
Authorization: Bearer {apiKey}
{ "model": "{modelStandard|modelAdvanced}", "stream": true, "temperature": 0.2,
  "messages": [ {"role":"system","content":"<prompt>"}, {"role":"user","content":"<text>"} ] }
```

**两阶段**

| 阶段 | 模式 | 输出 | 用途 |
|---|---|---|---|
| Stage1 | stream=true | 纯译文增量 | 首屏秒出（首 token ≤800ms） |
| Stage2 | stream=false | 严格 JSON | 词条 / 例句 / 用法 / 出处 |

```json
{ "source_lang": "en", "target_lang": "zh-Hans", "translation": "……", "mode": "word|sentence|ocr",
  "senses": [{"pos": "n.", "defs": [{"def": "鸟；禽", "examples": [{"src": "a bird in the hand", "tgt": "一鸟在手"}]}]}],
  "synonyms": [{"word": "fowl", "note": "家禽"}],
  "usage": [{"title": "give sb. the bird", "body": "起哄、喝倒彩"}],
  "notes": ["口语中也可指年轻女子，注意语域"] }
```

- Stage2 失败或 JSON 不合法 → 带强约束重试一次；仍失败则隐藏细节 tab，保留译文（**降级不伤主流程**）。
- 超时：连接 5s / 单次 25s；429、5xx 重试 1 次（退避 800ms）；401/403 直接提示鉴权失败。
- 缓存：`(text, pair, tier, mode)` → 译文 + 细节，TTL 30min，LRU 200；命中 ≤50ms。
- 「标准/高级」= 换 model（也可同 model 换 `reasoning_effort` / `max_tokens`），下一次请求即生效。

**Prompt 约束**

1. 只输出目标语言译文，不解释、不加引号；专有名词保留原文。
2. OCR 模式保留原换行结构，逐行对应。
3. 单词模式必须词性分组，例句带原文与译文。
4. 中文默认简体全角标点（可设置为繁体），英文半角。
5. 不确定的术语/语域写进 `notes`，不得在 translation 里加括注。

### 6.5.1 机器翻译引擎（2026-11-06 追加：默认引擎）

产品口径：**新增机器翻译，且默认走机器翻译；AI 翻译降为可选项**。目的是「装上就能译」，不再强制用户先配端点与密钥。

- 引擎枚举：`TranslationEngineKind = machine | ai`，设置项 `translate.engine`，默认 `machine`。
- 机器翻译服务商：`MachineTranslationService = auto | youdao | myMemory | google`，设置项 `translate.machineService`，默认 `auto`（回退链 有道 → MyMemory → 谷歌）。
- 接口（全部免密钥）：
  | 服务 | 端点 | 方式 | 语言码 |
  |---|---|---|---|
  | 有道 | `https://aidemo.youdao.com/trans` | POST form `q/from/to` | `auto` / `zh-CHS` / `zh-CHT` / `en` … |
  | MyMemory | `https://api.mymemory.translated.net/get` | GET `q` + `langpair=src|tgt`（不支持 auto，本地按 Unicode 脚本猜） | `zh-CN` / `en` … |
  | 谷歌 | `https://translate.googleapis.com/translate_a/single` | GET `client=gtx&sl&tl&dt=t&q` | `auto` / `zh-CN` / `zh-TW` … |
- 响应解析：有道取 `translation[]`（`errorCode != 0` 即失败）；MyMemory 取 `responseData.translatedText`（`responseStatus != 200` 或正文含 `MYMEMORY WARNING` 视为额度失败）；谷歌取嵌套数组每段第 0 项拼接。
- 分块：按 UTF-8 字节上限切（有道 3000 / 谷歌 1800 / MyMemory 450），优先句末标点，结果按 `\n` 拼回；超长无标点单句按字符硬切。
- 超时与回退：单次默认 8s（`translate.machineTimeoutMs`），不重试；自动模式下任一家失败立即换下一家，全挂时错误文案点名每一家并提示可切 AI。
- 事件形态：机器翻译非流式，固定「一个 `.delta(全文)` + finish」，卡片复用原有流式消费逻辑；不产出 `.detail`，因此词条 tab 自然隐藏。
- 密钥：机器翻译**不读 apiKey**；只有 AI 引擎才走 `missingAPIKey` 闸门。卡片顶栏「机器 / AI」是会话级切换（不写回设置），设置页的「默认引擎」才持久化。
- 缓存：键增加引擎维度（`engine \u{1F} text \u{1F} pair \u{1F} tier \u{1F} mode`），机器译文与 AI 译文互不覆盖。
- 兼容：`AppSettings.Translate` 改为逐字段 `decodeIfPresent`，旧版设置 JSON 缺 `engine/machineService/machineTimeoutMs` 时补默认值，**不得整份重置**（热键、划词黑名单会一起丢）。

### 6.5.2 交互稳定性修订（2026-11-06 实测）

**卡片外观**：悬浮卡的阴影必须交给 NSPanel 的窗口阴影（`hasShadow`）。SwiftUI `.shadow` 只能画在 hosting view 内部，会被窗口边界裁成一圈硬边灰框（用户称为「底框」）；`stroke` 描边同理。`DarkCard` 现在只有圆角背景 + `clipShape`，不画 stroke / shadow。

**选区读取**：`AXSelectionReader`（kAXSelectedTextAttribute）→ 失败则 `ClipboardSelectionReader`（快照剪贴板 → 合成 ⌘C → 350ms 轮询 changeCount → 读串 → 按 changeCount 决定还原）。Electron / 自绘控件不支持 AX 选区属性，以前直接落到「剪贴板里没有文本」，这是「翻译选区经常不能用」的主因。

**OCR 卡死（已复现并修复）**：
- 现象：日志停在 `截图完成` 之后，没有 `OCR 完成`，之后所有热键都被 `isRunning` 挡掉，直到重启。
- 根因：Vision 文本识别在冷启动时要加载模型（本机实测 **30.4s**）；预热跑在 `.background` 的 detached task 上，accessory App 被 App Nap 节流时可能长时间不返回，而预热与正式识别当时并发调用 Vision，正式请求就一直等不到。
- 修复：① 预热与识别统一走 `VisionTextRecognizer.serialQueue` 串行；② 预热改 `userInitiated` 并 `beginActivity(.userInitiated)` 抑制 App Nap；③ `OCRVision.recognizeWithTimeout` 硬超时（预热完成 12s / 未完成 45s + toast）；④ `CaptureFlow` 看门狗 75s 强制复位、热键重入超过 40s 自动复位；⑤ 日志区分冷启动与正常识别。
- 实测：冷启动 `prewarmMs=30435` → `ocrMs=758`（整屏 3456×2234，85 行）；同机二次 `prewarmMs=122` → `ocrMs=720`。命令：`--ocr-smoke`。

**OCR 自动朗读**：`TranslationSession.present(editable:)` 打开即 `speakIfEnabled()`（此前只有非 OCR 路径朗读）；`confirmOCR` 用 `skipIfSpeakingSame` 避免同一段重复打断，文本被改过才重读。

### 6.6 朗读（SpeechKit）

```swift
protocol SpeechEngine {
    var id: String { get }
    var needsNetwork: Bool { get }
    func voices(for lang: String) async -> [VoiceOption]
    func speak(_ text: String, voice: VoiceOption?, rate: Float, volume: Float) -> AsyncStream<SpeechEvent>
    func stop()
}
```

| 实现 | 内存增量 | 首字延迟（目标） | 语言覆盖 | 启用条件 |
|---|---|---|---|---|
| `SystemSpeech`（AVSpeechSynthesizer） | ≈0 | ≤80ms | 系统全部音色，中英日韩法德俄西葡齐全 | 默认 |
| `OpenAISpeech`（`POST /audio/speech` + `AVAudioPlayer`） | 流式，≈0 | 300–900ms | 取决于端点支持 | 用户填了语音模型时可选 |
| `LocalSherpa`（ONNX，可选下载） | 150–250MB | 150–400ms | 中文（vits-piper-zh_CN-huayan / matcha-icefall-zh-baker）、英文 | 用户显式开启「离线高质量」 |

- 分句：正则切句 → 队列（≤3 句预取）→ 顺序合成 → 单 `AVAudioPlayer` 顺序播放；切句间隙 <40ms 视为无缝。
- 语种 → 音色：`LangCode` 映射到 AVSpeech `language`（`zh-CN` / `en-US` / `ja-JP` / `ko-KR` / `fr-FR` / `de-DE` / `ru-RU` / `pt-BR` / `es-ES`），用户可对每种语言锁定具体 `AVSpeechSynthesisVoice.identifier`。
- 音色列表显示：名称、语言、质量（default / enhanced / premium）、试听。
- 失败降级：云/本地引擎失败 → 自动回落 `SystemSpeech` 并 toast 一次；系统引擎失败 → 静默失败 + tooltip。

### 6.6.1 引擎切换与本地引擎部署（2026-10-30 追加：本地 sherpa-onnx 与系统引擎并列，均可手动切换）

- 设置项：speech.engine = system | sherpa | openai，UI 为三段式选择器，切换即生效；sherpa 下再选模型（vits-piper-zh_CN-huayan-medium 快 / matcha-icefall-zh-baker 自然）与说话人。
- 部署形态（本版）：随包不放模型；scripts/install-sherpa.sh 下载 sherpa-onnx macOS 预编译包 + 两个中文模型到 ~/Library/Application Support/TranslationReader/models/sherpa-onnx/，逐文件 sha256 校验，失败即回滚删除半成品。
- 调用形态：sherpa-onnx-offline-tts 子进程逐句合成 wav → AVAudioPlayer 播放；wav 按 sha256(text|model|speaker|speed) 落 ~/Library/Caches/TranslationReader/tts/（LRU 500 条）。
- 首字延迟由预取掩盖：播放第 N 句时已在合成第 N+1 句；首次合成冷启约 300-600ms，后续句间歇 ≤40ms 无缝。
- 后续优化（M5，不在本版）：改为常驻 helper 进程 + stdin/stdout 协议或 C API 直连，消除进程冷启。

## 12. 已拍板（2026-10-30，用户确认）

1. **技术栈 = Swift 原生 + SwiftPM**（不做 Tauri/Electron）。若日后要 Windows 版，另立文档重估，本轮不改栈。
2. **朗读引擎 = 系统 AVSpeechSynthesizer 与本地 sherpa-onnx（VITS / Matcha）并列，可手动切换**（2026-10-30 追加要求）。

   - 任一引擎失败 → 自动回落系统引擎并 toast 一次。

> 由此冻结的三条硬约束：浮条与弹窗必须 nonactivating；译文区不得出现喇叭按钮；Stage2 失败只能隐藏细节 tab，不得影响译文与朗读。
