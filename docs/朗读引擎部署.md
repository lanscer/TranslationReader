# 朗读引擎部署（SpeechKit）

本文覆盖文档 §6.6 / §6.6.1 的两套引擎：系统 AVSpeechSynthesizer 与本地 sherpa-onnx。
云端 /audio/speech 档（openai）本版不实现，SpeechKit.makeEngine(kind: .openai) 返回 nil。

---

## 1. 引擎切换（立即生效）

设置项落 AppSettings.Speech.engine（UserDefaults 键 settings.speech），三段式选择器由 AppShell 接线；
持久化读写走 SpeechSettingsStore 协议，语音实现不碰存储细节。

```swift
import SpeechKit

let service = SpeechService(store: UserDefaultsSpeechSettingsStore()) { error in
    // 本地引擎失败自动回落系统引擎，这里只弹一次 toast
    print(error.userMessage)
}
service.setEngine(.sherpa)   // 立即生效：先 stop 旧引擎，再写设置
service.setEngine(.system)
let engine = service.currentEngine
```

- 播放中切换：setEngine 内部先 previous.stop() 再改设置，不会两个引擎同时出声。
- 失败降级：本地引擎抛错（模型缺失、子进程失败）→ 自动改用系统引擎重播同一段文本，
  fallbackNotice 只在本次会话报一次。
- 引擎实例由 SpeechService 持有；SpeechKit.makeEngine(kind:) 是纯工厂。

sherpa 档的模型偏好另存（AppSettings.Speech 无模型字段、Contracts 冻结）：

```swift
var pref = SherpaModelPreference.load()      // 默认 huayan（快）
pref.modelID = SherpaModelCatalog.baker.id   // 切"自然"档
pref.save()
```

## 3. 安装 / 校验 / 卸载

```bash
bash scripts/install-sherpa.sh                  # 幂等安装
bash scripts/install-sherpa.sh --force          # 强制重下
bash scripts/install-sherpa.sh --skip-english   # 只装中文
bash scripts/install-sherpa.sh --root /tmp/x    # 装到别处（调试）
```

脚本行为：

1. 每个产物下载后立刻 shasum -a 256 比对钉死的哈希，不符即删除并换下一个源。
2. 解包到 .staging-* 再原子搬进目标目录；任一步失败就删除该项半成品并退出非 0。
3. 已存在且校验通过 → 打印「跳过下载」，不重复下载（幂等）。
4. 全程不调用 sudo，不写系统目录。

## 5. CLI 实测参数（以官方 --help 实际输出为准）

本机实测：bin/sherpa-onnx-offline-tts --help 里的相关 flag（v1.13.8 与 v2.0.1 都含）：

```
--vits-model                : Path to VITS model (string, default = "")
--vits-tokens               : Path to tokens.txt for VITS models (string, default = "")
--vits-lexicon              : Path to lexicon.txt for VITS models (string, default = "")
--vits-data-dir             : (v1.13.8) espeak-ng 数据目录；v2.0.0 起 Deprecated/忽略
--vits-length-scale         : Speech speed. Larger->Slower; Smaller->faster. (float, default = 1)
--matcha-acoustic-model     : Path to matcha acoustic model (string, default = "")
--matcha-vocoder            : Path to matcha vocoder (string, default = "")
--matcha-tokens             : Path to tokens.txt for Matcha models (string, default = "")
--matcha-lexicon            : Path to lexicon.txt for Matcha models（可用逗号分隔多个）
--matcha-length-scale       : Speech speed. Larger->Slower; Smaller->faster. (float, default = 1)
--sid                       : Speaker ID（多说话人模型才用）
--num-threads               : Number of threads to run the neural network (int, default = 1)
--output-filename           : Path to save the generated audio (string, default = "./generated.wav")
```

一条可直接复制、本机实测通过的合成命令（华研中文，输出 22050 Hz 单声道 16bit wav）：

```bash
ROOT="$HOME/Library/Application Support/TranslationReader/models/sherpa-onnx"
M="$ROOT/models/vits-piper-zh_CN-huayan-medium"
"$ROOT/bin/sherpa-onnx-offline-tts" \
  --vits-model="$M/zh_CN-huayan-medium.onnx" \
  --vits-tokens="$M/tokens.txt" \
  --vits-data-dir="$M/espeak-ng-data" \
  --output-filename=/tmp/huayan.wav \
  "今天天气不错，我们出去走走吧。"
# 实测输出：Elapsed seconds: 0.277 s / Audio duration: 2.810 s / RTF 0.099
```

Matcha（中文·自然，需要 vocoder）：

```bash
M="$ROOT/models/matcha-icefall-zh-baker"
"$ROOT/bin/sherpa-onnx-offline-tts" \
  --matcha-acoustic-model="$M/model-steps-3.onnx" \
  --matcha-vocoder="$ROOT/models/vocoder/vocos-22khz-univ.onnx" \
  --matcha-tokens="$M/tokens.txt" \
  --matcha-lexicon="$M/lexicon.txt" \
  --output-filename=/tmp/baker.wav \
  "大家好，欢迎使用本地语音合成引擎。"
# 实测输出：Audio duration: 3.610 s / RTF 0.116
```

App 内部调用的参数拼装见 Sources/SpeechKit/SherpaRunner.swift 的
SherpaCLIRunner.arguments（单测 SherpaRunnerTests 覆盖）：短句单次子进程合成，
--sid 用设置里的说话人，--*-length-scale = 1 / 倍速。

## 6. 性能实测（2026-10-30，本机 macOS 27.2 / arm64 / Swift 6.4.2）

复现方式（测量口径不变，静音播放把 volume 传 0）：

```bash
SPEECHKIT_LIVE_TTS=1 swift test --skip-build --scratch-path .build-speech \
  --filter '(Speech|Sherpa|Sentence)'
```

### 6.1 系统引擎（AVSpeechSynthesizer）首字延迟

口径：从调用 speak 到首个 willSpeakRangeOfSpeechString 回调（真正开始发音），各 3 次。

| 语种 | 3 次实测 | 中位数 |
|---|---|---|
| zh-Hans（今天天气不错，我们出去走走吧。） | 55.4 ms 级 ×3 | 55.4 ms |
| en（Good morning, this is a latency test.） | 208.4 / 44.8 / 34.7 ms | 44.8 ms |

en 的第一次 208.4 ms 是进程内首次调用合成器的冷启开销。

### 6.2 本地引擎（sherpa-onnx v1.13.8 + 华研 medium）首字延迟

口径：从调用 speak 到首个 boundary 事件（第一句 wav 开始播放），3 次。

| 次数 | 状态 | 首字延迟 |
|---|---|---|
| 第 1 次 | 冷启（子进程冷启 + 首次合成 3 句） | 975.5 ms |
| 第 2 次 | 缓存命中 | 7.7 ms |
| 第 3 次 | 缓存命中 | 9.5 ms |
| — | 中位数 | 9.5 ms |

英文（Amy medium，冷启）：1276.2 ms。
文档 §6.6.1 预估的冷启 300-600 ms 比本机实测乐观；实测偏大的原因是 3 句都要起子进程、
首句还要加载 onnx 模型。缓存命中后已与系统引擎持平。

### 6.3 切句间隙（预取深度 3）

口径：第 N 句 started 打点 减去 第 N-1 句 finished 打点。

| 次数 | 各间隙 | 最大 |
|---|---|---|
| 第 1 次 | 6.5 / 1.1 ms | 6.5 ms |
| 第 2 次 | 1.6 / 3.6 ms | 3.6 ms |
| 第 3 次 | 7.8 / 12.1 ms | 12.1 ms |

结论：全部远低于 40 ms，满足「切句间隙 < 40ms 视为无缝」。

### 6.4 打断（stop）实测

口径：播放中点 stop，到 AsyncStream 收到 finished 的耗时。

| 引擎 | stop 到流结束 | 说明 |
|---|---|---|
| 系统引擎 | 0.1 ms | stop() 先 stopSpeaking 再就地结束所有未完成流（不依赖滞后的 didCancel） |
| 本地引擎 | 2.9 ms | 停 AVAudioPlayer + 取消合成任务 |

注：AVSpeechSynthesizer 的 didCancel 回调实测滞后约 326 ms，所以 stop() 不能等它；
声音本身在 stopSpeaking 返回前已停。

### 6.5 第二次复跑（缓存已热）

| 项目 | 第一次实测 | 第二次复跑 |
|---|---|---|
| 系统引擎 zh-Hans 首字延迟中位数 | 55.4 ms | 43.5 ms |
| 系统引擎 en 首字延迟中位数 | 44.8 ms | 43.8 ms |
| 本地引擎中文冷启 | 975.5 ms | 89.7 ms（缓存已热，非冷启） |
| 本地引擎缓存命中 | 7.7 / 9.5 ms | 10.1 / 18.0 ms |
| 本地引擎英文 | 1276.2 ms（冷启） | 84.4 ms（热） |
| 切句间隙最大值 | 12.1 ms | 8.7 ms |

### 6.6 wav 规格（ffprobe）

| 文件 | 采样率 | 声道 | 时长 |
|---|---|---|---|
| 华研中文「今天天气不错，我们出去走走吧。」 | 22050 Hz | 1 | 2.810 s |
| Matcha 中文「大家好，欢迎使用本地语音合成引擎。」 | 22050 Hz | 1 | 3.610 s |
| Amy 英文「The quick brown fox…」 | 22050 Hz | 1 | 3.256 s |

缓存目录实测 4 个 wav（三句中文各一份）共 568 KB，文件名即 sha256(text|model|speaker|speed)。

## 7. 故障排查

**Q1 本地引擎报「缺少本地模型 / 请先运行 scripts/install-sherpa.sh」**
跑 bash scripts/install-sherpa.sh。就绪判定 = bin/sherpa-onnx-offline-tts 可执行 + 该模型目录里有
onnx 与 tokens.txt（Matcha 还需要 models/vocoder/vocos-22khz-univ.onnx）。

**Q2 为什么钉死 v1.13.8，不用最新的 v2.0.x**
v2.0.0 起官方移除 espeak-ng 前端（--vits-data-dir 变成 Deprecated/忽略）。实测 v2.0.1 跑华研中文直接失败：

```
offline-tts-vits-impl.h:Tokenize:324 phoneme_codepoints is empty, no lexicon, and no frontend available.
offline-tts-vits-impl.h:Generate:112 Failed to convert the text to token IDs
Error in generating audio. Please read previous error messages.
```

piper 系 zh_CN / en_US 模型都依赖 espeak-ng 音素化，所以本版用 v1.13.8；Matcha 系在 v2.0.x 仍可用。
将来升级要么给 piper 模型补 lexicon，要么换模型族。

**Q3 下载卡住 / 0 B/s**
GitHub releases 直连在本机实测 0 B/s（objects.githubusercontent.com 超时，curl 报 HTTP2 framing error）。
脚本会自动按 直连 → gh-proxy.com → gh-proxy.net 回退；手工下载示例：

```bash
curl -L --http1.1 -C - -o vocos-22khz-univ.onnx \
  https://gh-proxy.com/https://github.com/k2-fsa/sherpa-onnx/releases/download/vocoder-models/vocos-22khz-univ.onnx
```

**Q4 首次播放有将近 1 秒的停顿**
缓存未命中时每句都要起子进程（冷启见 §6.2）。第二次起命中缓存即 10 ms 级；
预取深度已按文档上限 3，调大只会增加并发子进程与内存，收益有限。

**Q5 清缓存**
rm -rf ~/Library/Caches/TranslationReader/tts。LRU 上限 500 条，超出自动淘汰最久未用。

**Q6 切换引擎后还是旧声音**
SpeechService.setEngine 会先 stop 旧引擎再写设置，下一次 speak 即新引擎；
不要自己缓存 SpeechEngine 实例，每次用 service.currentEngine 取。

**Q7 英文读不出声（本地引擎）**
install-sherpa.sh --skip-english 会跳过 Amy 模型，此时英文应回落系统引擎；
补装直接去掉该参数重跑脚本。

**Q8 测试框架报 TestingMacros 插件找不到**
本机 CommandLineTools 环境下，全量并行构建偶尔会让某个 test target 的 @Test/@Suite 宏失效
（external macro implementation type 'TestingMacros.TestDeclarationMacro' could not be found），
与源码无关。用串行构建取证：先逐 target swift build --target XxxTests，再 swift test --skip-build。
