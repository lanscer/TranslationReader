> 3. 账号页新增「拉取模型列表」（GET {baseURL}/models，成功后可一键填标准/高级档）、模型名占位提示「示例：deepseek/deepseek-v4.1-flash（多数网关要求厂商前缀）」、测试连接失败时的**可复制诊断行**（baseURL + 模型名 + HTTP 状态 + 网关原文）。证据：`settings-account-models.png`(700×620)、`settings-account-400.png`(700×700)，两态均由本地桩端点真跑（200 → 5 个带前缀模型 35ms；400 → 网关原文）。

## 2. 复现命令

```bash
cd ~/Documents/DeepSeek_hs/全局翻译自动朗读

# 构建（串行，避免多 teammate 并发污染 SwiftPM 插件缓存）
swift build --scratch-path .build-integration

# 单测（全绿，146 个）
make test SCRATCH=.build-integration

# 打包 .app
make app

# ① 验收数字（RSS / 冷启动 / OCR / 首字延迟 / 引擎切换 / 八语种 / 卡片落位）
./.build-integration/debug/TranslationReader --selftest

# ② 视觉证据（不依赖屏幕录制权限，UI 离线渲染成 PNG）
./.build-integration/debug/TranslationReader --render-evidence

# ③ 双链路冒烟（本地 OpenAI 兼容桩端点，真 HTTP + SSE）
node .build-integration/stub-openai.js 8787 &
TR_SMOKE_BASE_URL=http://127.0.0.1:8787/v1 TR_SMOKE_API_KEY=sk-stub \
  ./.build-integration/debug/TranslationReader --chain-smoke

# ④ 常驻内存（两个档位，可复现 M0 判据）
BIN=~/Applications/TranslationReader.app/Contents/MacOS/TranslationReader
TRANSLATIONREADER_NO_PREWARM=1 "$BIN" & sleep 3; ps -o rss= -p $(pgrep -f 'TranslationReader.app/Contents/MacOS' | head -1)
"$BIN" & sleep 10; ps -o rss= -p $(pgrep -f 'TranslationReader.app/Contents/MacOS' | head -1)
```

### 链路 ②（截图 OCR → 确认态 → 译文）

```
CHAIN|chain2|ocrMs=89|lines=3|text=Translation should be fast. / 原文朗读优先，译文不发声。 / QuiCK brown fox 2026.
EVIDENCE|chain2-ocr-confirm-real.png  viewport=420x273
CHAIN|chain2|translateMs=239|translationLen=24|hasDetail=1
EVIDENCE|chain2-ocr-result-real.png  viewport=420x317
```

界面路径：⌥S → 全屏遮罩拖框（Esc 取消 / Space 全屏）→ 松手截图 → Vision OCR → 卡片进入**可编辑确认态** → 「翻译并朗读」→ 译文 + 细节 + 朗读原文。

> 本机 AX 未授权，所以两条链路的「取词」起点用剪贴板/手动输入/合成图代替真实选区与真实拖框；**除了这两个交互起点，其余代码路径与真实使用完全一致**。

## 7. 已知限制与偏离（必读）

1. **辅助功能未授权（AXIsProcessTrusted = false）** — 本进程无法读真实选区，因此：
   - 「真实划词 → 浮条 → 翻译」的端到端**没有**在本机跑通，浮条定位与闸门只到单测级；
   - 已用三条不需要 AX 的路径代替取证：⌥Space（读剪贴板）、菜单「翻译剪贴板」、菜单「手动输入…」；
   - 授权后要跑：见 §8。
2. **本机无可用 chat 端点** — 翻译数字全部来自**本地 OpenAI 兼容桩**（真 HTTP + 真 SSE + 真 Stage2 JSON），文档 §9 允许「仅桩验证」。用户填好 baseURL/apiKey 后重跑 `--selftest` 会打印 `translateFirstTokenMs`。
3. **idle RSS 与 Vision 预热是一对硬取舍**：
   - 不预热：82.5 MB（满足 M0 <90MB），但**首次** ⌥S 会卡 30.8 s（Vision 首次装载）；
   - 预热：123.4 MB（超出 M0 预算 33MB），OCR 首调降到 ~0.1 s。
   - 本版默认**预热**（体验优先），并留 `TRANSLATIONREADER_NO_PREWARM=1` 供「内存优先」档位验证。若 M0 的 <90MB 是硬指标，建议 M5 改成「用户在设置里勾选预加载」或「空闲 30s 后再预热」。
4. **sherpa 冷启 1120 ms** — 子进程 + 模型装载，超过文档 150–400ms 预估；缓存命中后 82–120 ms。M5 改常驻 helper 或 C API 直连才消。另：本地模型只覆盖中文（华研/Matcha）与英文（Amy），日/韩/法/德/俄/葡/西会**回落系统引擎**（有 toast，只报一次）。
5. **⌥S 的「拖框」无法自动化** — 遮罩等待真人鼠标；本次只验证了「截图之后」的全自动段（OCR→确认态→翻译→朗读）。
6. **菜单栏图标可能被系统挤出** — 本机状态栏项非常多（媒体控制、各 App 状态项），新加的状态项会被 macOS 隐藏到老大难的溢出区；已用 `NSStatusBarWindow` 自检日志证明项已创建。用户可拖动/精简状态栏项让它露出。
7. **ad-hoc 签名** — `make app` 未找到「TranslationReader Dev」证书，用 ad-hoc 签名：每次重建 TCC 授权都会失效，需要重新勾选（跑 `./scripts/make-signing-cert.sh` 可解决）。
8. **未做的验收项** — M1「浮条 ≤150ms」、M3「10 行混排」「繁体抽查 3 例」、M4「apiKey 磁盘搜不到」的**运行期**取证：前两项被 AX/样本限制，后一项只到实现级（本次未写入真实 key）。
